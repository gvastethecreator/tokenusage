# TokenUsage 0.0.1 Preview 2

Local usage, clearer comparisons, and daily updates for Windows x64.

> [!WARNING]
> This is an **unsigned preview for Windows x64**, distributed as a portable ZIP. Windows may show an unknown-publisher or SmartScreen warning. No MSIX installer is included. Use it for evaluation, not as a signed or fully qualified stable release.

## Highlights

- **Daily updates.** Opt in under **Options → General** to check GitHub once every 24 hours while TokenUsage runs. Manual checks, download progress, cancellation, and retry are included. Updates wait until you exit; they do not interrupt an active task.
- **Better usage comparisons.** Compare date ranges, weeks, models, and two to four recorded Codex reset cycles. Each comparison identifies its provider. Cost, token totals, coverage, and observed activity remain distinct.
- **More readable reports.** Choose smooth lines, straight lines, steps, daily bars, two-hour bars, or stacked areas. Group by provider or model, switch chart styles in the report, and use the optional small-value scale when totals differ widely.
- **A cleaner desktop interface.** Options use four consistent tabs with icons, aligned switches, and smoother height changes. Compact quota cards keep two balanced columns. Report actions sit beside the title; chart controls sit beside the chart views.

## Reports and measurement

- Sort the complete model, provider, and day tables by their column headers. Model and provider rows include active-day counts.
- Spot days with recorded resets through chart markers, with provider and reset details in the tooltip and keyboard help.
- Read cached input, uncached input, and output below the chart. Export captures without window controls or action buttons.
- Keep reported costs, price estimates, unpriced tokens, and missing data separate. API-rate estimates are not subscription charges.
- Avoid idle-use forecasts and preserve valid Grok usage when the source does not identify a model.

## Update safety

- Includes the matching Windows App SDK runtime resource required for portable notification startup. The first unpublished candidate failed this check and was discarded.

- Downloads must match GitHub's SHA-256 digest and asset size. Drafts, pre-releases, older versions, and incompatible packages are rejected.
- Portable updates preserve `Data` and unrelated files, skip identical files, and keep recovery backups for changed files.
- Direct MSIX updates require a trusted signature and matching package identity. Microsoft Store continues to manage Store installations; development registrations do not self-update.
- Automatic checks send no usage data or provider credentials. The setting is off by default.

## Install and upgrade

| Distribution | How to use it |
| --- | --- |
| `TokenUsage-0.0.1-win-x64-portable-unsigned-preview.zip` | Extract the whole archive into a writable folder and run `TokenUsage.App.exe`. Run `tokenusage.cmd` for the CLI. |
| `SHA256SUMS.txt` / `release-manifest.json` | Check download integrity, source commit, architecture, and the unsigned-preview channel. Hashes are not a publisher signature. |

Keep `TokenUsage.portable` and the portable `Data` folder. The app and CLI share that folder. MSIX uses separate app data; switching distributions does not migrate it.

Install this preview manually. It is not delivered by automatic updates. Its updater can receive future **stable** releases with an application version newer than 0.0.1. This first release has no public predecessor for an end-to-end upgrade check.

## Known limits

- Provider coverage depends on each tool's available local data. Catalog entries do not all have active readers, and missing quotas are never invented.
- Reset-cycle comparisons currently use Codex history. Gaps in recorded history remain visible.
- This candidate targets Windows x64. ARM64 is a build target but has no release asset or runtime qualification here.
- Direct MSIX auto-update requires Windows 10 version 2004 or later. See the [requirements](https://github.com/gvastethecreator/tokenusage#requirements) before installing.
- Recovery after a power loss during portable replacement can require manual action. Backups remain available; fully automatic pre-start recovery is not claimed.

## Verification

The implementation passed 1,375 tests and the x64 Release app/MSIX build. Native checks covered the update settings, daily schedule, download errors, cancellation, and rejected corrupt downloads. An isolated portable worker check verified replacement, unchanged-file skipping, data preservation, and recovery-file retention.

Signed installation and upgrade, clean-machine checks, and hard-power-loss recovery remain unqualified. See the [release procedure](https://github.com/gvastethecreator/tokenusage/blob/main/docs/RELEASING.md) for the preview and stable publication gates.
