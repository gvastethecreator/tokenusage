# Z.ai GLM Coding Plan quota gate

Fecha de corte: 2026-07-21

Decisión: `block`

## Pregunta

¿Puede una app Windows pública consultar la cuota restante del GLM Coding Plan con una API key que entrega el usuario, mediante una interfaz documentada para región, cuenta y uso por terceros?

## Respuesta

Z.ai ofrece una consulta oficial de cuota para el plan Personal, pero la publica como plugin para Claude Code. No publica esos endpoints en su OpenAPI general ni autoriza de forma expresa a una app de escritorio independiente. TokenUsage no implementará el cliente Z.ai ni pedirá su API key mientras falte un contrato público para ese uso o permiso escrito.

El gate queda bloqueado, con opción de reabrirlo. La fuente existe; su alcance actual no cubre nuestro producto.

OpenUsage sirve solo como comparación local: `robinebers/openusage@9d2bf09f10e21f769494a525a9d65c84d7aeb1df` llama `GET /api/biz/subscription/list` y `GET /api/monitor/usage/quota/limit`. Su cliente agrega `Bearer` al header. El plugin oficial envía el valor de `ANTHROPIC_AUTH_TOKEN` de forma directa. Esta diferencia confirma que no debemos tratar el código upstream como contrato.

## Delegación y review

Grok Build hizo forense local sin web y propuso `block`. El resultado está en `.scratch/agent-cli-delegation/grok-build/runs/2026-07-22T00-16-55-621Z-plan-7b7238f2/result.json`: `EndTurn`, siete turnos y USD 0.2202356 reportados por el CLI local.

El parent review encontró el plugin oficial publicado después del corte upstream, fijó su commit y reabrió todas las fuentes primarias. Ese hallazgo cambió la evidencia: el endpoint ya tiene una implementación oficial, con alcance limitado a Claude Code. La decisión sigue bloqueada por falta de contrato para TokenUsage.

## Hallazgos

### Cuota

El plugin oficial prueba que Z.ai expone datos de uso y cuota. Su documentación fija dos límites de alcance:

- plan Personal;
- ejecución dentro de Claude Code.

El script oficial usa estas bases según la cuenta:

| Cuenta | Base |
|---|---|
| Z.ai internacional | `https://api.z.ai` |
| BigModel China | `https://open.bigmodel.cn` |

Sobre cada base consulta:

- `/api/monitor/usage/model-usage`;
- `/api/monitor/usage/tool-usage`;
- `/api/monitor/usage/quota/limit`.

El repositorio público muestra una implementación, pero el OpenAPI general no ofrece esquema, compatibilidad, permisos o ciclo de retiro para esos paths.

### Autenticación y permisos

El plugin usa `ANTHROPIC_AUTH_TOKEN` y deriva la región desde `ANTHROPIC_BASE_URL`. Las fuentes revisadas no definen scopes de solo lectura para una app aparte ni una key limitada a cuota. TokenUsage tendría que guardar una key capaz de usar el plan, con más permiso que el dato que busca.

### Uso permitido

Los términos hablan del consumo de beneficios del plan y no describen de forma concreta una lectura de cuota desde otra app. Aun así, la documentación limita el plugin oficial a Claude Code y la política advierte sobre herramientas e integraciones no soportadas. Inferimos que el permiso para TokenUsage no está establecido. Nuestro gate exige permiso claro y por eso falla cerrado.

### Alternativa de gasto

El OpenAPI público no ofrece billing o usage de cuenta. Los `usage` devueltos por una respuesta de modelo solo cubren esa llamada y requieren que el cliente participe en ella. TokenUsage no hará llamadas de modelo para medir gasto.

El motor local podrá atribuir tokens y coste estimado a modelos Z.ai cuando un agent soportado ya los registre. Esa vista será `Uso local observado`, con cobertura, y no una cuota o factura de Z.ai.

## Decisión de producto

- No crear un provider remoto Z.ai en la beta pública.
- No solicitar ni guardar una API key Z.ai.
- No invocar los endpoints del plugin ni automatizar Claude Code.
- No copiar el adaptador de OpenUsage.
- Permitir que el motor local agrupe observaciones de modelos Z.ai provenientes de logs admitidos.
- Reabrir el gate cuando Z.ai publique un API de cuota para terceros, una integración oficial para TokenUsage o permiso escrito que cubra endpoint, auth, región y cuenta.

## Incertidumbre restante

Z.ai puede ampliar el plugin a otras herramientas o agregar sus paths al OpenAPI. La decisión corresponde a la documentación del corte indicado y debe revisarse antes de una beta que anuncie soporte Z.ai.
